### 1.1 원칙

- **읽는 건 AI, 계산은 규칙 (R-24, PER-002)**: 나누기 · 환산 · 차감은 `packages/shared` 의 함수만 한다. 같은 입력이면 항상 같은 결과
- **계산 규칙 (PER-003)**: 1/N + 줄별 배정, 세금은 몫 비율대로, 통화별로 따로, 남는 금액은 낸 사람이 부담
- **저장하지 않는다 (AVL-004)**: 시연은 한 기기, 여러 기기 동기화는 범위 밖. Vercel 함수는 요청마다 메모리가 비워질 수 있으므로 서버는 보낸 데이터로 계산만 하고, 데이터는 화면이 들고 있다

## 2. 한 일 자세히

### 2.1 데이터 형식 (`packages/shared/src/schemas.js`)

- 결제자 여러 명 `payers`, 참여자 확인 `confirmations` (맞아요 / 안 갔어요), 나눌 사람 `memberIds`
- 영수증 줄의 세금 구분 `kind`, 한국어 번역 `nameKo`, AI 질문 `Question`
- 결제일 환율 `fx`, 가게 이름 `merchant`, 상품 분석 항목 연결 `planItem`
- 지갑 잔액의 카드/현금 `WalletBalance`, 현금 주고받기 `CashTransfer`, 상품 분석 결과 `Estimate`
- 분류 값은 프로토타입이 이미 쓰는 한국어 `식사 · 선택관광 · 교통 · 쇼핑 · 팁 · 기타`

### 2.2 계산 (`packages/shared/src/settle.js`, `budget.js`) - "읽는 건 AI, 계산은 규칙" (R-24)

| 함수 | 하는 일 | 요구사항 |
| ---- | ------- | -------- |
| `expenseShares` | 기본 1/N, 줄별 배정, 세금은 몫 비율대로, "안 갔어요" 빼고 다시 나누기, 남는 금액은 낸 사람 부담 | PER-003, R-06, R-11 |
| `settle` · `minTransfers` | 통화별 몫 · 낸 돈 · 차액 · 보낼 돈, 사람별 원화 합계 (결제일 환율) | R-06, R-19, R-20 |
| `checkExpense` | 결제자 합 = 총액, 줄 합 = 총액, 명단 밖 이름, 세금 줄 배정 검사 | R-09 |
| `applyExpense` · `applyCashTransfer` · `replayWallets` | 확인 끝난 지출을 지갑에 반영, 카드 잔액 부족 → 현금 주고받기 (줬어요 · 받았어요 둘 다) | R-05, R-12, R-13 |

| `report` | 상품가 + 내 몫 = 진짜 총비용, 항목별 예상 vs 실제 | R-22 |
| `daySummary` | 오늘 내 몫, 통화별 잔액, 이 속도면 부족한 금액 | R-23 |

### 2.3 API (`apps/api`)

`GET /fx` (Frankfurter v2 결제일 환율 → 없으면 ExchangeRate-API), `POST /settle`, `/settle/wallets`, `/settle/wallets/replay`, `/settle/day`, `/settle/duplicates`, `/budget`, `/report`, `/trips/:tripId/receipts/analyze`.
서버에 저장하지 않고 보낸 데이터로 계산만 한다 (Vercel 함수 메모리, 요구사항 AVL-004 한 기기 시연).
AI 사용 한도 초과는 503 "AI 사용 한도를 넘었어요" 로 돌려주고, 화면은 직접 입력으로 넘긴다.

### 2.4 AI (`packages/ai`)

원격 `feat/ai` 에 새 작업이 없어서(2026-11-04 확인) BE 담당이 구현했다. AI 담당과 겹치지 않게 공유가 필요하다.

- `readReceipt`: 영수증 사진 → 줄 단위 (메뉴 · 수량 · 금액 · 세금 · 한국어 번역 · 원문). 금액 최소 단위 변환은 코드가 한다
- `assignLines`: 말 → 줄별 나눌 사람. 이름 → id 변환과 명단 밖 이름 거르기는 코드가 하고, 애매하면 질문으로 넘긴다
- `runPipeline`: 검사(줄 합 = 총액)가 틀리면 틀린 점을 알려 주고 1회 다시 읽기, 그래도 남은 오류는 질문
- `npm run eval` (PER-001): 케이스(영수증 + 말 + 정답)마다 `runPipeline` 을 돌려 줄 금액 일치율 · 합계 일치율 · 배정 정답률 · 틀린 결과를 잡아낸 비율 · 평균 시간을 내고 `eval/results/` 에 저장. `--no-retry` 로 재시도 켬/끔 비교. 케이스는 예시 영수증 1개(`eval/cases/001`). 실행은 키가 있어야 한다

2026-11-04 영수증 분석을 실제로 호출하자 Anthropic API 가 다음과 같이 거절했다.

> You have reached your specified workspace API usage limits. You will regain access on 2026-12-01 at 00:00 UTC.

해커톤 API 키가 속한 작업공간의 사용 한도가 찼고, 12월 1일까지 풀리지 않는다는 뜻이다. 이 키로 Claude 를 부르는 기능은 지금 전부 실패한다.

| 기능 | 영향 |
| ---- | ---- |
| 상품 문구 분석 `/estimate` | 튀르키예 예시 문구만 저장된 결과로 동작 (프로토타입에 있던 대비책) |
| 말 · 카드 문자 · 영수증 합계 기록 `/record` | 실패 → 직접 입력으로 넘어감 |
| 영수증 줄 단위 분석 `/receipts/analyze` | 실패 → 직접 입력으로 넘어감. 새 AI 코드는 실호출로 확인하지 못함 |

- 같은 날 로컬 `.env` 에서 해커톤 키를 뺐다. 키가 없으면 AI 기능은 503 "AI 키가 설정되지 않았어요" 를 돌려주고 화면은 직접 입력으로 넘어간다. 다른 키를 넣으면 코드 수정 없이 다시 동작해야 한다
- **대응 (같은 날)**: 배포 사이트(hanatour-290.vercel.app)는 팀원 키로 동작하는 것을 확인했다. 로컬에 키가 없으면 `/estimate` · `/record` 를 배포본으로 넘기도록 했다 (`.env` 의 `AI_UPSTREAM`, `apps/api/src/lib/upstream.js`). 브라우저로 확인: 상품 분석(실제 AI), "기념품 300리라 현금" → 쇼핑 ₺300 현금, 예시 카드 문자 → 괴레메 카페 ₺620, 예시 영수증 → 합계 ₺3,560 · 4명
- 배포본은 아직 프로토타입 코드라 영수증 **줄 단위** 분석(`/receipts/analyze`)은 없다. 그래서 영수증은 줄 단위 → 실패 → 합계 읽기로 넘어간다. 줄 단위는 이 코드가 배포되거나 로컬에 키가 있어야 동작한다
- 시연 영상: 시나리오 1 · 3 · 5 · 6 · 7 은 지금 찍을 수 있다. 시나리오 2 의 "말로 줄별 나누기" 는 배포 후 가능
- 한도는 해커톤 측이 작업공간에 정한 값이라 코드로 풀 수 없다. 운영진에게 한도 증액 · 새 키를 요청하거나 다른 키를 `.env` 의 `ANTHROPIC_API_KEY` 에 넣으면 코드 수정 없이 동작해야 한다
- 누가 얼마나 썼는지는 오류만으로 알 수 없다. 확인된 사실: BE 담당의 Claude Code 가 2026-11-03 22:15 ~ 2026-11-04 04:37 사이 해커톤 키로 동작하도록 설정돼 있었다. 앱(로컬 · Vercel 배포본)이 Claude 를 부를 때도 `.env` 의 API 키 사용량으로 쌓인다 (Max 요금제와 별개). 정확한 내역은 키를 발급받은 계정의 Claude Console → Usage 에서 작업공간 · 키별로 확인할 수 있다
